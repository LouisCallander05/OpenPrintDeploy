# OpenPrintDeploy 0.10.0

This release combines automatic driver delivery, a responsive tray menu, faster
zone editing, and an integrated domain login page.

## Changes

- The client includes a Local SYSTEM driver service. It downloads eligible signed
  packages from the configured print server, verifies them, and prepares drivers
  before the user's printer connection is created. Changes to server drivers are
  checked during sync, including for existing assigned printers.
- Printer connections use the prepared local driver without opening an admin
  credential prompt. Blocked installations are reported as sync failures.
- The tray menu remains responsive during background sync. Manual sync can show
  the running cycle's result without starting a second cycle.
- Zone editing opens immediately from loaded zone data. Directory group names
  load in the background, with cached results and protection against late lookups
  overwriting edits.
- The admin website uses a domain username/password form over HTTPS, secure
  eight-hour sessions, and a Sign out button. Existing `Auth:AdminScheme=Basic`
  settings migrate to the form; explicit `Negotiate` settings retain Windows SSO.
- Domain passwords are validated at sign-in rather than on every page request.
  Native validation has bounded concurrency and a request timeout; domain-service
  failures no longer count as incorrect-password attempts.
- Client sync retains Windows Integrated Authentication and remains separate
  from browser admin sessions. Existing older clients can continue to sync;
  automatic driver delivery requires the new client and server.

## Install and upgrade

1. Install `OpenPrintDeploy.Server.msi` on the print server. Back up application
   data and any customised `appsettings.json` before upgrading. Application data
   is retained; review custom configuration after the upgrade.
2. Open the server's HTTPS admin page and sign in with an authorised domain
   account. Restarting the server service ends browser sessions.
3. Download the configured client MSI from the updated server dashboard and use
   it to upgrade client devices. Preserve its generated filename, or supply the
   server, certificate pin, and any allow-list MSI properties when deploying.
   The generic GitHub client MSI needs deployment configuration.

The MSIs include their .NET runtime. Upgrades from the 0.10 beta MSIs are
supported even though Windows Installer records the same numeric product version.

## Validation and remaining limits

Pilot testing reported successful printing with KONICA MINOLTA Universal PCL and
Lexmark Universal v2 queues, plus successful server-driver update testing.
Automated tests cover driver delivery, sync, login/session protections, and zone
editing. Vendor and policy compatibility still need a staged rollout.

A prior Windows 11 lab spooler crash involving HP/Brother queues remains
unresolved; this release does not claim to fix that Windows spooler failure.
The new login flow also needs validation with the target domain configuration;
it does not establish the root cause of the previously reported server hang.

Signed vendor packages can still require administrator deployment of an approved
signing certificate to Local Computer Trusted Publishers. OpenPrintDeploy does
not automatically trust publishers or relax Windows driver-installation policy.
See [driver delivery requirements](../driver-delivery.md) for supported packages,
server topology, troubleshooting, and pilot checks.
