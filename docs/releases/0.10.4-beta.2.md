# OpenPrintDeploy 0.10.4-beta.2 candidate

Fixes beta 1's missing Lexmark connections after automatic repair. The vendor
driver could match the server while a separate Microsoft core package was not
staged, causing the normal user's reconnect to fail with elevation error 740.

## Driver preparation

- Export each declared core driver's complete signed Driver Store package
  alongside the vendor package. Include core versions and package contents in
  the export cache fingerprint, so Windows core updates invalidate the bundle.
- Upload each core package separately through the existing bounded SYSTEM
  installer before installing the vendor driver. Windows checks each package's
  catalog/signature; no INF edits or loose spooler-file installation are used.
- Verify that every required package is Windows-published in the local Driver
  Store, or that Windows already has a sufficient registered core version.
  Windows may retain an older default core registration after successfully
  staging the server's package; that does not require changing the default.
- Check live server core requirements before disconnecting any existing queue,
  and again before adding a normal user connection. Incomplete preparation
  defers repair and leaves an existing connection installed.
- Use a fresh protected client cache (`OpenPrintDeploy-DriverClient-v2`). Do not
  adopt legacy cache contents after permissions have allowed untrusted writes.
  This can repeat driver preparation once; it does not reinstall every queue.

## Upgrade order and compatibility

Upgrade the server first, then the clients. Older clients ignore the additional
manifest fields and continue using their existing connection behavior. A new
client talking to an older server defers core-dependent driver preparation with
an update-required error; self-contained vendor drivers remain supported.

Beta 1's interrupted repair snapshots are retained. Once preparation succeeds,
the normal sync can re-add a missing queue and restore its supported saved
preferences without disconnecting it a second time. Completed migrations are
not repeated solely because the client version changes.

No database migration is required for this fix. MSI ProductVersion remains
0.10.4 with same-version upgrades enabled; application version is
0.10.4-beta.2. This candidate has not been published to GitHub.

## Validation

- 343 automated tests pass in Release, including core dependency versions,
  missing/older-server metadata, staging order, shared-package deduplication,
  failed signature/upload behavior, readiness before disconnect, and native
  entry-point/ABI checks.
- On the pilot laptop, staging the server's Microsoft-signed core package
  allowed A6 Office and Science Lab Tech to connect as the standard user,
  using normal silent shared-printer connections. Both advertise duplex.
- The complete new native package-installation pipeline passed in an elevated
  pilot using the signed Lexmark and Microsoft packages. The production child
  installer retains its existing SYSTEM-only entry-point guard.
- Saved standard preferences were restored; A6 Office defaults to OneSided /
  Letter and Science Lab Tech to TwoSidedLongEdge / A4. Both managed connection
  revisions were saved as complete, with original snapshots archived.
- The user physically tested two-page double-sided jobs on both Lexmark queues
  and confirmed successful duplex output.

A full upgraded server/client delivery run remains a pilot check before a
broader rollout. Existing beta 1
limits concerning vendor-private finishing/accounting settings still apply.
