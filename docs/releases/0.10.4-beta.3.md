# OpenPrintDeploy 0.10.4-beta.3 candidate

Fixes false driver-mismatch failures when migrating Type 4 shared printers.
Windows can use the Microsoft enhanced Point and Print driver on the client
while the server queue uses the prepared vendor driver. This is a supported
configuration; querying GetPrinterDriver through a queue handle can return the
client projection even when that handle bypasses the cache.

## Change

- Verify the prepared local package's name, environment, date and version.
- Query the actual server share and its driver using server-side printer and
  driver enumeration, rather than comparing the client rendering driver with
  the vendor package. This also applies to connection creation and the live
  server check before disconnecting for repair.
- Continue blocking missing/ambiguous shares, unavailable server metadata,
  changed server drivers and incomplete core-package preparation before any
  disconnect. Driver mismatch messages now include expected and actual values.
- Keep connection revision 1. Only pending migrations retry; successful beta 2
  migrations do not repeat solely because beta 3 is installed.

This is a client-side fix and works with the beta 2 server. Install the beta 3
client on the affected pilot laptop, then verify its next sync completes and
the three pending queues still print correctly. No server upgrade is required
for this pilot. Stable 0.10.4 publication remains on hold pending that check.

## Validation

- 358 Release tests pass with dependency auditing, including actual-server
  identity selection, Type 4 rendering projections, changed/missing drivers,
  ambiguous/missing shares, invalid paths and native entry-point/ABI checks.
- On the working pilot laptop, all three Type 4 connections use Microsoft's
  enhanced driver while the server queues use Lexmark Universal v4 XL.
  The previous check rejects this configuration; the corrected preflight passes.
- A controlled VCE Staffroom Type 4 reconnect under the standard user preserved
  duplex, default printer, paper, colour and duplex preferences. Replaying
  recovery did not reconnect the printer again.
- The supplied failed-laptop log shows five completed migrations and three
  safely deferred Type 4 queues: VCE Staffroom Printer, Staffroom Printer and
  Music Room Printer. The user confirmed those three remain listed and print.

Microsoft documents the Type 4 client/server driver distinction in
[Work with enhanced Point and Print](https://learn.microsoft.com/en-us/windows-hardware/drivers/print/working-well-with-enhanced-point-and-print).
