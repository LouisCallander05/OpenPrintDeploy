# OpenPrintDeploy 0.10.2

Fixes a server upgrade failure introduced by the storage hardening in 0.10.1.
Existing beta/0.10.0 installations can inherit a `BUILTIN\Users: Write` rule
from ProgramData. Version 0.10.1 rejected that rule during startup, causing the
MSI to report error 1920 (service failed to start).

## Fix

The server MSI now runs a narrowly scoped permissions migration before starting
the service. It accepts the legacy inherited, container-only Users Write rule
or its equivalent explicit copy only on a SYSTEM/Administrators-owned directory, then replaces the directory
ACL with protected SYSTEM/Administrators access. It checks existing database,
journal and admin-settings files before allowing startup. No database or
configuration content is deleted or rewritten by this migration.

Normal service startup remains strict. Unexpected owners, explicit broad write
grants, redirected paths and unsafe file permissions still require administrator
review. The migration takes no caller-supplied path and only runs as SYSTEM
against the default server data directory. Custom database locations are not
modified. Tightened permissions remain if a later installer step rolls back;
older SYSTEM services can still access their data.

## Upgrade

Back up server data/configuration as usual, then run the **0.10.2 Server MSI**
over the existing installation. If the 0.10.1 installer is still showing an
error, cancel it and let rollback finish before starting the new MSI. No manual
folder-permission command should be necessary for the reported legacy ACL.

Client printing behavior is unchanged from 0.10.1. A matching client MSI is
included, but this particular failure is fixed by upgrading the server.
The other [0.10.1 configuration requirements](0.10.1.md) still apply.

## Validation

Regression tests cover the precise inherited ACL, refusal of broader permissions
and untrusted owners, strict normal startup, and an elevated Windows filesystem
migration preserving existing contents and refusing writable files. The release
workflow builds and tests both installers. Full MSI upgrade and printing on the
affected domain server remain deployment validation steps; this release does
not claim those remote tests have already been performed. Packages are unsigned.
