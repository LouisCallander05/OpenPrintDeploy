# OpenPrintDeploy 0.10.3

Client reliability update for automatic driver preparation and shared-printer
connections.

## Fixes

- Fixes intermittent "Unable to read beyond the end of the stream" failures
  introduced by the driver-service pipe lifetime change in 0.10.1. The service
  now lets the tray read its response and close the connection before reusing
  the pipe. The wait is bounded, and the protected first pipe instance remains
  reserved between requests.
- When explicit binding to a verified local driver returns Windows error 3012
  ("No printers were found"), the tray retries once with standard Windows driver
  selection. Both attempts prohibit dialogs and retain Windows security policy
  enforcement. Missing or changed prepared drivers still block the connection.
- Logs when the standard silent connection succeeds, and reports both attempts
  when it fails, including the final Windows error.

## Upgrade

Upgrade the **Client MSI** on affected workstations to receive these fixes.
Keep the same server address, certificate pin, and print-server allow-list. For
an installer downloaded from the server dashboard, preserve the generated
filename; for managed deployment, supply the existing MSI configuration
properties.

Clients remain compatible with a 0.10.2 server. The **Server MSI** bundles the
0.10.3 client so the dashboard can distribute the current installer; upgrading
the server is optional for client compatibility. The 0.10.2 server storage
upgrade fix is retained.

Upgrades from 0.10.3-beta.1 are supported even though Windows Installer records
both as numeric version 0.10.3. This release contains the same client fixes as
that test build.

## Validation and limits

270 automated tests cover the existing suite plus real named-pipe response
delivery with delayed readers and reused connections, cancellation/recovery,
invalid extra requests, and connection fallback control flow. The release
workflow tests the solution and builds both Windows MSIs.

Pilot logs showed that interrupted driver-service replies stopped after the
test update. The tester subsequently reported OpenPrintDeploy working under
another user profile on the same PC. The original profile's FQDN printer
connection failure remains unresolved and also occurs through Windows Explorer;
this release does not claim to repair that profile or establish its root cause.
Fallback unit tests do not establish compatibility with every Windows policy
or vendor driver. Packages are unsigned.
