# OpenPrintDeploy 0.10.1

Security hardening for the server, tray, SYSTEM driver service and uninstall
cleanup introduced or reviewed with 0.10.0. Automatic driver preparation and
updates retain the existing workflow; this release does not automatically trust
driver publishers or relax Windows driver installation policy.

## Changes

- Admin user grants match the full authenticated account name or primary user
  SID. Same-named accounts in other domains no longer match a qualified grant.
- Production first-run setup requires server Administrators membership.
- Existing admin sessions are checked during browser circuit activity and
  periodically revalidated after logout or changes to OPD admin grants.
- Uninstall cleanup uses protected machine storage and immutable requests.
  Each user reads their own managed state; SYSTEM no longer reads profile files.
- Protected storage rejects untrusted ownership, unsafe write permissions and
  redirected paths. The default server database and admin grant store receive
  additional protection.
- Printer-server allow-lists require exact hostnames. Sync requests refuse
  redirects and scope default Windows credentials to the configured server.
- Production refuses insecure HTTP fallback. LDAP certificate bypass and Basic
  LDAP without TLS are rejected; explicit-domain lookups fail closed.
- Driver archive extraction responds to cancellation, checks extracted lengths
  and rejects additional Windows device names. The service retains its named
  pipe instance between requests.
- Updated native SQLite and the bundled .NET runtime (8.0.33), enabled transitive
  dependency auditing in CI and pinned release actions to commit identifiers.

## Before upgrading

1. Back up application data and customised configuration. Record a working
   qualified admin account (`DOMAIN\user`) or group SID in protected break-glass
   configuration. Bare username grants no longer match qualified accounts.
2. Confirm HTTPS/certificate trust and directory TLS settings. Unsafe transport
   configurations now fail instead of being silently accepted.
3. List required short names and FQDNs separately in the print-server allow-list.
4. Check existing data directory ownership and permissions. Do not grant ordinary
   users write access to resolve a permissions failure.
5. Review obsolete uninstall tasks and cleanup artifacts from earlier versions.
   An old pending cleanup task is not automatically retired by a normal upgrade.

Install the server MSI on a pilot print server, then download its configured
client MSI from the dashboard for the pilot workstation. The generic client MSI
attached here still needs the server address, certificate trust/pin and any
additional allowed-server settings supplied by the deployment administrator.

## Validation and limits

The audit's automated suite passed 247 tests, and both MSIs built successfully.
The transitive dependency rescan reported no known vulnerable packages. These
results do not replace live domain, browser-session, service-permission and MSI
upgrade/uninstall testing. Complete the isolated VM checks before broad rollout.

The packages are unsigned unless a release signing identity is configured.
A compromised trusted print server can still provide an unsafe signed driver;
Windows signing and publisher policy remain important controls. Previously
reported vendor/spooler compatibility issues are not claimed fixed here.

.NET 8 support ends on 10 November 2026; a supported-runtime migration is still
required. This self-contained release bundles its runtime patch, so endpoints
must receive a rebuilt application package for future bundled-runtime updates.
