# OpenPrintDeploy 0.10.0 security audit

Date: 26 October 2026. Baseline: published tag `v0.10.0`, commit
`78adcc4eef246acab16a372a34072e6d1296ccf2`. Remediation branch:
`security/audit-0.10`. This report and its fixes are local; the published 0.10.0
MSIs have not been replaced.

## Assessment

**Do not treat the released 0.10.0 as security-cleared for a broad rollout.**
The review found authorization defects and unsafe privileged filesystem
operations. Local fixes and regression tests address the findings below, but
the patched build needs an isolated domain/Windows pilot before release.

This is a source, dependency, configuration and packaging audit, not a security
certification. No real local privilege-escalation exploit was executed. No
school server, domain policy, print queue or production endpoint was changed.
The result cannot establish that abuse is impossible.

## Scope and method

Reviewed the SYSTEM driver service, named-pipe protocol, machine configuration,
driver download tickets, HTTPS transport, archive extraction and Windows driver
installation; tray sync and UNC validation; server routes, forms/Windows
authentication, sessions, admin authorization, LDAP, persistence and zone
administration; elevated installer/uninstall cleanup and release workflows.

Evidence includes source tracing, tests of hostile inputs and authorization
decisions, loopback redirect tests, Windows ACL descriptor tests, NuGet's
transitive advisory scan, self-contained builds and MSI packaging. Existing
tests cover ticket protection, archive/path validation, printer reconciliation,
API authentication, input validation and reporting. A targeted secret-pattern
scan found no matching committed-source credentials; this is not an exhaustive
history or credential audit.

Evidence labels below distinguish directly testable application behavior from
potential exploit chains that require live Windows validation. Severity is a
qualitative assessment of impact and prerequisites, not a calculated CVSS score.

### A01–A03: admin identity and sessions

`AdminAccessEvaluator` now compares the full authenticated account name, normally
`DOMAIN\user`, or `ClaimTypes.PrimarySid`. A group SID cannot satisfy a user SID
grant. Production never falls back to a username-only LDAP lookup to reconstruct
missing token groups. Development retains its stub-directory behavior.

An empty configuration now permits bootstrap only with enabled token group SID
`S-1-5-32-544` (server Administrators). Deny-only membership does not qualify.
Corrupt/unreadable admin storage remains sealed, with configured break-glass
grants available for recovery.

`AdminSession` gives stored tickets an internal session identifier.
`AdminCircuitGuard` checks that session and current OPD grants before inbound
Blazor activity. `AdminAuthenticationStateProvider` also revalidates every 15
seconds. This protects open pages as well as new HTTP requests. Tests invoke
the guard before and after revocation and ensure protected work is not called.
They do not emulate a complete browser/SignalR connection. In-flight work is
not rolled back by logout. AD group membership is still a sign-in-time snapshot
for the session's maximum eight-hour lifetime.

Sources: [Blazor security](https://learn.microsoft.com/en-us/aspnet/core/blazor/security/)
and [circuit authentication guidance](https://learn.microsoft.com/en-us/aspnet/core/blazor/security/additional-scenarios).

### A04–A05: privileged storage and cleanup

Uninstall gather now obtains profile SIDs only from HKLM ProfileList. Each
standard-user cleanup process reads its own managed state and removes only
Created-origin printers; adopted printers remain. The v2 request is stored in
`%ProgramData%\OpenPrintDeploy-Cleanup`, writable only by SYSTEM/Administrators
and readable by users. Completion markers and user logs stay in each user's
profile. Privileged logging uses stdout/MSI logging, not an appendable shared
file. Task XML uses a random, exclusive-create file inside protected storage.

`PrivateDirectory` rejects reparse ancestors, untrusted owners and mutation
rights granted to untrusted identities before adopting storage. Existing
sensitive files are checked before use. Default SQLite storage, sidecars and
the admin-grant file use these checks. Grant-file saves use exclusive temporary
files followed by replacement. These controls assume the parent location itself
has normal Windows protection. They do not defend against an administrator who
can already change ownership, ACLs, service binaries or machine configuration.

The original path operations are confirmed in source; arbitrary SYSTEM code
execution through them has not been demonstrated. Remaining Windows-specific
checks include junction races, precreated directories/files, real MSI token
ownership, task permissions and upgrade compatibility.

### A06–A09: transport and identity boundaries

Both tray and service require exact allowed print-server hostnames. For example,
allowing `print.school.example` does not allow `print.attacker.example` or `print`.
Short names must be explicitly added if required. Malformed UNC paths, alternate
data stream syntax and embedded NULs are rejected. Empty lists deny connections.

Tray HTTP clients refuse redirects. Default Windows credentials use a
`CredentialCache` scoped to the configured URI and Negotiate. The driver service
already refuses redirects and accepts only its machine-configured HTTPS origin;
the caller cannot provide a download URL or credentials.

LDAP Basic requires TLS; Negotiate without TLS requires signing and sealing.
`AllowInvalidCertificate=true` is rejected. An unresolved explicit domain cannot
fall through to a different domain's same-named user. Forest group-name grants
require a single SID match; incomplete discovery/search can deny access. Use
configured group SIDs for critical break-glass access.

Production now requires usable, enforced HTTPS. Security response headers also
deny framing and object embedding, restrict the base URI, disable MIME sniffing
and limit referrer sharing. These headers supplement existing Razor escaping,
antiforgery and authorization; they are not a full script-nonce CSP.

### A10–A11: dependencies and build provenance

The original transitive scan reported `SQLitePCLRaw.lib.e_sqlite3` 2.1.6 under
[GHSA-2m69-gcr7-jv3q](https://github.com/advisories/GHSA-2m69-gcr7-jv3q).
The server now pins `SQLitePCLRaw.bundle_e_sqlite3` 2.1.14, which brings updated
native/provider packages. A test opens a real native SQLite connection and
requires `sqlite_version()` to be at least 3.50.2. A clear dependency scan means
no currently reported advisory matches, not that packages contain no defects.

CI now scans transitive dependencies when NuGet audit is enabled. GitHub actions
are pinned to reviewed upstream commit identifiers; CI has read-only repository
permissions, while the release workflow retains the write permission it needs.
Self-contained publishing pins .NET 8.0.33, and Negotiate is updated to 8.0.33.
The published 0.10.0 MSIs were inspected and are unsigned; local audit MSIs are
also unsigned because no signing identity is configured.

The [Microsoft support policy](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core)
lists .NET 8 support ending on **10 November 2026**. Plan a supported-runtime
migration promptly. Self-contained applications require rebuilt/redeployed
packages to receive runtime patches; installing a newer shared runtime on the
server alone is insufficient.

## Driver service: protections and remaining limits

The reviewed interface does not accept arbitrary commands, executables, local
paths, registry keys, URLs or user credentials. It accepts a bounded queue/ticket
request over a local pipe, validates machine policy, retrieves the server's
manifest/archive and uses Windows package installation APIs. The implementation
checks download hashes, archive size/count/path limits and signed-package
installation. Download hashes detect mismatches, but their manifest and payload
come from the same trusted server.

The named pipe denies network tokens and grants authenticated local users
read/write without the create-instance right. The service now retains its first
pipe instance between requests. The client connects at anonymous impersonation
level. Requests and response waits are bounded, jobs are serialized, and archive
extraction now observes cancellation and rejects additional console-device
aliases. See [Microsoft's pipe security documentation](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights).

Important residual risks:

- **A compromised trusted print server or OPD administrator is still highly
  privileged.** It can offer a validly signed but unsafe driver. Signature and
  publisher trust checks cannot prove safety. Preserve driver-signing policies,
  control server administration, and validate applicable Windows driver block
  rules. See [Microsoft's vulnerable-driver guidance](https://learn.microsoft.com/windows/security/threat-protection/windows-defender-application-control/microsoft-recommended-driver-block-rules).
- Download tickets are short-lived bearer capabilities (30 minutes), not bound
  to a particular machine. Theft can enable replay of the ticket's scoped
  operation while valid. Never log tickets. A ticket does not grant arbitrary
  command execution or arbitrary server access.
- An authenticated local process can repeatedly occupy the single IPC worker.
  There is no per-user fairness/quota. Some native spooler/driver discovery calls
  are not interruptible by the managed cancellation deadline. This remains an
  availability risk, as do bounded-but-stuck native authentication workers.
- Directory endpoint discovery uses process-lifetime lazy state. A failure or
  incomplete forest discovery may require a service restart. Caches also mean
  group-name changes are not instant. This review does not prove that all causes
  of the previously reported server hangs are resolved.
- Installed service, task and directory ACLs, Windows native APIs, vendor
  drivers, the print spooler and domain trust are not fully exercised by unit
  tests. The earlier `localspl.dll` crash is not proven to be a security flaw or
  resolved by this audit.
- Legacy EXE installer paths were read but only MSI artifacts were packaged in
  this validation. A nonstandard service identity or custom database location
  needs explicit permission review; hardened defaults target Local SYSTEM.

## Upgrade prerequisites

Before installing a patched pilot:

1. Back up configuration and the database. Record an exact qualified admin user
   or known admin group SID in protected break-glass configuration. Bare username
   grants no longer match qualified Windows identities. A UPN only matches when
   it is the actual authenticated account name.
2. Confirm HTTPS/certificate trust and LDAPS settings. Production HTTP fallback,
   LDAP invalid-certificate bypass and Basic LDAP without TLS are rejected.
3. List each required short hostname/FQDN explicitly in the machine/client
   print-server allow-list. Do not rely on first-label aliases or empty lists.
4. Inspect existing data/storage ownership and ACLs. The patched application
   refuses unsafe storage rather than silently adopting it. Do not solve a
   failure by granting Users write access. Custom DB paths need equivalent
   protections supplied by the administrator.
5. Inspect any legacy `OpenPrintDeploy\Remove Managed Printers` scheduled task
   and old `%ProgramData%\OpenPrintDeploy\pending-removal.json`/`uninstall`
   artifacts. Normal upgrade does not automatically retire an earlier pending
   cleanup task. An administrator should retire obsolete tasks before the pilot;
   do not delete the entire shared OpenPrintDeploy data directory.
6. Review the cleanup change: v2 reads current managed state in each user's own
   context. The protected request does not shrink, and task expiry does not
   delete the staged cleanup executable. Remove that residual folder as an
   administrator once the cleanup window is over.

## Validation and release gate

The full automated suite passes **247 tests**, including the new cross-domain,
bootstrap, SID-type, revoked-circuit, protected-ACL, exact-host, redirect, unsafe
LDAP, HTTPS-startup and native SQLite checks. Solution builds succeed. Both MSI
packages build; WiX emits existing packaging warnings about same-version
upgrades, harvested-file language and deprecated standard-directory references.
The advisory rescan reports no vulnerable packages across the seven solution
projects. See `validation.json` for final artifact hashes and runtime evidence.

Still required in a disposable domain-joined Windows 11 / server pilot:

| Test | Expected result |
| --- | --- |
| Fresh setup as ordinary user, then server administrator | User denied; intended administrator can bootstrap. |
| Same username in two trusted domains; qualified grants and group SID grants | Only the explicitly granted identity is admitted. |
| Two open admin tabs; logout in one, then mutate in the other | Old tab cannot change data; reauthentication is required. |
| Remove an admin grant while its page remains open | Next protected action is refused. Also test idle/background refresh. |
| Expired/replayed/tampered tickets, wrong queue, unlisted host, redirect and invalid TLS | Request fails without installing anything or forwarding credentials. |
| Corrupt/unsigned/untrusted driver; altered archive; traversal/device path | Safe failure; no external file writes or partial connection creation. |
| Standard user precreates a cleanup/data path or a harmless junction canary | Service/uninstall refuses the unsafe path; target canary is untouched. |
| Inspect service, pipe, registry, scheduled task, binary and data ACLs | Standard users cannot replace privileged code/configuration or register a competing pipe instance while the service owns it. |
| Repeated malformed/idle local requests; service restart | Other clients recover; document remaining serialization/availability limits. |
| MSI upgrade/uninstall with two users, Created and Adopted printers | Only intended Created printers are removed; adopted/manual printers survive; user cannot edit another user's request. |
| Normal print, driver update, reboot and sign-in as a standard domain user | Printing succeeds without interactive admin prompts or weakened Windows driver policy. |

Do not merge or publish a security release on the strength of unit tests alone.
Record the pilot results and address failures before promoting these packages.
